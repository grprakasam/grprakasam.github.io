How I architect an agent

ADAM AI is my reference design. Each stage is a decision I wrote down as an architecture decision record (ADR), and each one exists because a regulated reviewer will ask about it.

  1. 1Spec inADaM specification, YAML or Excel
  2. 2GenerateLLM drafts the R program; cheap model firstADR 0004
  3. 3Static gatessafety, syntax, variable coverage, CDISC namingADR 0002
  4. 4Sandboxed runR in a container with no networkADR 0009
  5. 5Compareevery variable against an independent referenceADR 0006
  6. 6Human sign-offan independent reviewer; the requester cannot approveADR 0003

Repair loop. Any failure at stages 3 to 5 goes back to stage 2 with the evidence: the error, or the mismatched variables with example subjects. Repeated failures escalate to a stronger model, then to a person.

  • Durable stateLangGraph checkpoints in SQLite, so a paused review survives a restart · ADR 0010
  • Tamper-evident auditevery step in a hash-chained log · ADR 0005
  • Cost controltokens and cost per run, in USD and INR · ADR 0004
  • Tools for other agentsthe deterministic checks exposed as an MCP server · ADR 0007

ADAM AI

Proof of concept on clinical data

A LangGraph agent turns a CDISC ADaM specification into an R program, runs it in a network-isolated sandbox, compares the output with an independent reference and stops for a person to sign off. Every step goes into a hash-chained audit log.

Workflow modernization agent

Track 1 of my agentic AI learning lab, built and tested offline

Converts legacy SharePoint- and Nintex-style workflows into Power Automate drafts. Deterministic rules go first and a bounded LLM second; anything left over is flagged for a person. A differential test then checks that each draft behaves like the original.
